Clerk Integration CourtOS

Authentication & organisation membership via Clerk, authorization enforced server-side in Convex.

│  Browser                                                    │

Roles

Role Source Access
Super Admin isSuperAdmin flag on users table /admin, all org dashboards, promote other admins
Org Admin Clerk org role org:admin /$slug/* — CRUD tournaments, venues, players, scores
Member Authenticated user + participants table (not in Clerk org) /dashboard — view tournaments they're added to, rankings (read-only)
Unauthenticated — / landing page, /kiosk/* public display

Data Flow

Sign-in

User signs in via Clerk modal (SignInButton)
ConvexProviderWithClerk sends JWT to Convex on every request
UserSync calls users.upsert — creates or updates user doc with tokenIdentifier, name, email

Organisation Membership

Admins only are invited to Clerk Organisations (dashboard or API)
Admin's JWT includes org_id and org_role — used for mutation authorization
Members are not in Clerk orgs — they're linked via participants table. Admin adds them to tournaments.

Route Protection

Frontend checks useAuth().isSignedIn — redirects to / if false
Smart redirect: super admin / org admin → /$slug/tournaments, member → /dashboard
Backend mutations enforce auth as safety net — never trust client alone

Clerk Configuration

Clerk Dashboard

  • Create JWT template named convex with audience convex
  • Enable Organisations feature
  • Built-in roles: org:admin, org:member

Key Decisions

  • Clerk owns user lifecycle — no user create/delete in CourtOS, only sync on sign-in
  • Clerk orgs are admin-only — members don't join Clerk orgs, they're linked via participants table
  • Super admin is app-level — isSuperAdmin flag in DB, not a Clerk role
  • Queries are open — any authenticated user can read any org's data (spectators, kiosk)
  • Mutations are gated — server-side org membership + role checks on every write
  • Kiosk is public — no auth required for read-only display screens
